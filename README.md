# ScriptDrills

A TypeScript coding-drill sandbox: pick a random challenge, write the solution
in an in-browser editor, run it, and get instant pass/fail feedback plus an
explanation. Built with Vite, React 19, and shadcn/ui (Tailwind v4).

There's no backend — code execution, syntax highlighting, and all your
progress run entirely client-side in the browser.

**Live at [scriptdrills.magill.dev](https://scriptdrills.magill.dev/).**

## Getting started

Requires Node.js 20.19+ or 22.12+ (Vite 7's minimum).

```bash
npm install
npm run dev
```

Then open the printed local URL (defaults to `http://localhost:5173`).

### Other commands

```bash
npm run build        # type-check and build for production
npm run preview      # preview a production build locally
npm run typecheck    # tsc --noEmit
npm run lint          # eslint .
npm run lint:fix      # eslint . --fix
npm test              # run the test suite once
npm run test:watch    # run tests in watch mode
```

`npm install` also sets up git hooks via husky: a fast pre-commit hook
lints staged files, and a pre-push hook runs the type checker and full test
suite so nothing broken reaches the remote.

## How it works

- **Pick a challenge.** The Dashboard shows your stats and challenge history;
  "Start Random Challenge" picks one from
  [`src/data/drill-challenges.json`](src/data/drill-challenges.json).
- **Write your solution.** The editor ([CodeMirror 6](https://codemirror.net/))
  gives you TypeScript syntax highlighting. There's no hidden test harness —
  the code you write *is* the entire function body that gets executed. It's
  transpiled from TypeScript to JavaScript with
  [sucrase](https://github.com/alangpierce/sucrase) and run directly in the
  browser.
- **Get feedback.** Whatever your code `return`s is compared against the
  challenge's expected output. Correct, incorrect, and skipped attempts are
  all recorded to `localStorage`, so your stats and per-challenge history
  persist across visits — nothing is ever sent to a server.

### Architecture

- **Routing** is hand-rolled in [`src/App.tsx`](src/App.tsx) (no router
  library) — just two pages, Dashboard and Practice, switched on the URL path.
- **Pages** live in [`src/pages/`](src/pages): `Dashboard.tsx` (stats,
  activity log grouped by challenge, per-challenge history drawer) and
  `Practice.tsx` (the challenge workspace — editor, run/skip controls,
  console output, hints, explanation).
- **State and persistence** are managed in [`src/lib/storage.ts`](src/lib/storage.ts),
  a thin wrapper around `localStorage`. There's no database and no accounts.
- **The code editor** ([`src/components/CodeEditor.tsx`](src/components/CodeEditor.tsx))
  wraps CodeMirror 6 and is lazy-loaded — it's only fetched once you open a
  challenge, not on the initial page load, since it's the heaviest dependency
  in the app.
- **UI components** in [`src/components/ui/`](src/components/ui) are
  generated by [shadcn/ui](https://ui.shadcn.com/) — treat them as vendored,
  not hand-maintained application code.

For a deeper dive into the execution model, data conventions, and testing
setup, see [`CLAUDE.md`](CLAUDE.md) — it's written for AI coding agents
working in this repo, but it's a solid technical reference for humans too.

### Adding a new challenge

Challenges live in [`src/data/drill-challenges.json`](src/data/drill-challenges.json),
typed as `Challenge[]` (see [`src/types/index.ts`](src/types/index.ts)):
`id`, `title`, `description`, an optional `objective`, `hints[]`,
`starterCode`, `expectedOutput`, and `explanation`.

The most important rule: **`starterCode` must be an unsolved stub, not the
answer.** Whatever `starterCode` contains is exactly what loads into the
editor and gets executed if the user hits "Run Code" without changing
anything — so any solution logic left in there is a free answer. Keep any
fixture/setup code (`const`/`let` declarations the challenge is testing
against), but replace the actual solving logic with a `// TODO: ...` comment.

```ts
// Good starterCode - a real stub
const nums = [1, 2, 3, 4, 5];
// TODO: sum all elements and return the total
```

```ts
// Bad starterCode - this is the answer
const nums = [1, 2, 3, 4, 5];
return nums.reduce((acc, curr) => acc + curr, 0);
```

To add one:

1. Pick the next `ts-0NN` id (sequential, zero-padded to 3 digits).
2. Write `starterCode` as a self-contained script: fixture data plus a
   `// TODO` stub, ending in whatever `return` a correct solution would
   produce.
3. Work out a real solution and actually run it (transpile with sucrase,
   then execute the result) to get the exact `expectedOutput` string —
   copy the real runtime output rather than hand-typing it, since formatting
   like JSON key order and spacing has to match exactly.
4. Double-check the *unmodified* `starterCode` does **not** already satisfy
   `expectedOutput`.

See `CLAUDE.md` for more detail on the two supported `starterCode` shapes
(inline-fixture vs. function-under-test) and how the execution/comparison
model works under the hood.

## Deployment

The app is a static build with no backend, deployed to
[Cloudflare Workers static assets](https://developers.cloudflare.com/workers/static-assets/)
at [scriptdrills.magill.dev](https://scriptdrills.magill.dev/) via the native Git
integration — every push to `main` builds and deploys automatically, and
every pull request gets its own preview deployment.

To connect a new Cloudflare project to this repo (already done for the
production deployment above — these are the settings that were used):

1. In the Cloudflare dashboard, go to **Workers & Pages → Create**, and connect
   this repository.
2. Framework preset: **Vite** (or set manually — see below).
3. Build command: `npm run build`
4. Build output directory: `dist`
5. Leave the root directory as `/`.

Cloudflare reads the Node version to build with from
[`.node-version`](.node-version) automatically — no extra environment
variable needed.

### SPA routing

[`wrangler.jsonc`](wrangler.jsonc) sets `assets.not_found_handling` to
`"single-page-application"`, which serves `index.html` with a `200` for any
request that doesn't match a built file. This app uses real client-side routing
(`/practice` is pushed via `history.pushState`, not a `#/practice` hash), so
without it a direct link, bookmark, or refresh on `/practice` would 404 — only
in-app navigation would work.

> **Note:** don't swap this for a `public/_redirects` file with
> `/* /index.html 200`. That's the Cloudflare Pages-era approach; on Workers it
> fails the deploy with *"Infinite loop detected in this rule"* (error 100324),
> a known validator false-positive
> ([workers-sdk#11824](https://github.com/cloudflare/workers-sdk/issues/11824)).
